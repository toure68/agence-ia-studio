# Product invariants — Agence IA Studio

Preserve working behavior and approved design. A request to add a feature does not authorize replacing, removing, redesigning, or changing an existing feature. Change an established behavior only when the user explicitly requests that particular change. Keep unrelated work out of the change.

- Function buttons open a floating panel over the mounted cockpit. Keep the home address and document; do not turn module clicks into separate screens. Preserve cockpit scroll, assistant text and attachments. Keep an immediately available close cross and bottom close button.
- The assistant stays collapsed behind a compact bar (48px, 16px corners, centered label) just above the function grid, on the same row as the grid chooser button (user request 2026-10-18); opening/closing moves the existing chat into/out of the contextual panel while preserving history, draft and unsent attachments.
- Home cards stay closed by default with only a short action/status message. Details, fields and validation appear after a click in the panel.
- Preserve the approved dark translucent glass surfaces on a black cockpit background, colorful SVG app badges and discreet urgency indicators, responsive layouts, module visibility preferences, and access restrictions.
- Preserve existing business workflows, explicit validation, signature consent, and company/user isolation. Never send real messages or use paid provider calls during tests.
- Check affected workflows and navigation regressions before shipping. Inspect the final change for unrelated behavior changes. Verify deployment SUCCESS and live asset version before reporting the change online.

- Grid cards must always have identical dimensions; never span or stretch a last card. Keep overflow in the reserve. Four-column grids put icon cards above their labels; three columns retain rectangular inline widgets. Dynamic home is enabled by default: ten days of inactivity moves a module into reserve unless an actionable alert requires it; only an explicit user setting disables this behavior.

- Home widgets use inline SVG and CSS with a factual metric from the shared cockpit snapshot; no bitmap assets, per-card requests, invented figures or mixed-currency totals. Preserve equal cards, dynamic priorities and contextual navigation.

- All grid modes keep equal cells; the last row may be incomplete when fewer functions are checked (user decision 2026-10-18). Two-column widgets are horizontal with name and metric inside; four-column compact squares keep their labels below. Alert colors follow the explicit red danger/orange warning rule below; do not change unrelated detailed backgrounds.

- Two-column visual reference uses equal horizontal graphite glass cards, fine bright rims, large glass-backed colored SVG glyphs, uppercase names and wrapped factual metrics. Keep greeting, assistant, urgency banners and all workflows. Home search opens the existing searchable module reserve.

- Outer grid card corners are lightly rounded (10px). Three columns use smaller icons and inline labels/data; four columns keep labels below. Card heights now follow the common stable-height rule below. Preserve colors except the explicitly specified red/orange alert liseré.

- Current ergonomics: priority cards are independent and spaced, with the original graduated heights. Never combine all functions into one top panel. Show one card per function; several actions from the same function are accessible in its floating chooser. Preserve individual open, dismiss and speech actions. Two/four-column tiles retain a stable 88px mobile /112px desktop height. Three-column tiles scale their height, icon, text and insets together from the actual two-column cell width, including grid gaps. Recalculate on resize; every tile within a grid remains equal. Two/three-column buttons fit inside the outer card border. Priority borders use a masked 1px moving conic reflection on actionable grid and independent priority cards (8s linear loop); red/pink for danger, orange/gold for warning, static under reduced motion. No pulsing, layout changes or pointer interception. Every first-level/nested dialog must stay within the visual viewport including the keyboard; table scrolling stays local.

- The small glass app badge also has a steady 1px state rim: red danger, orange warning, blue info. Keep the colored glyph, glass fill, badge size and outer moving border unchanged; neutral and completed modules retain their normal rim.

- Event/required-date command preparation offers an explicit date picker, keeps dates written in the command working, and displays validation errors inline without hiding the Prepare button behind a toast. Creating a record still requires explicit confirmation.

- Home section titles ("À faire maintenant", "Vos modules") are visually hidden but kept for screen readers; blocks are separated by spacing only. Keep the column-chooser button visible.
- Home treasury is a read-only "watch dial" (docs/BANKS.md): header row (TRÉSORERIE, scope, status chip — the header alert chip opens the bank in deficit), ring of month in/out + balance + flows, one row of three equal always-visible buttons "Derniers" / "À venir" / "Voir tout →" above 3 rows, then a bottom row reserved for 36px round bank pills. "Tous" is always the default. Do not reintroduce the bank wheel or entry buttons on this card.
- The home grid button expands inline into 2/3/4 column squares that apply and save immediately (no form, no navigation).
- Home function grid row cap: the user picks 1–10 rows in the grid chooser (row stepper under the 2/3/4 column squares, applied and saved instantly); by default 2 columns → 3 rows (6), 3 columns → 3 rows (9), 4 columns → 2 rows (8). Grid cells are real functions only; home shows exactly the checked functions plus those with an action to do (danger/warning), and the last row may stay incomplete (user decision 2026-10-18: no automatic filler). Below the grid, the full-width "＋ Réserve de fonctions" button unfolds an inline container (no page, no panel) listing every function as a home-style card with a check: checked = on home, unchecked = reserve, saved on each tap. There is no "Tous les modules" text link.
- Home order: greeting, assistant, treasury, priorities, function grid, then the "＋ Réserve de fonctions" button attached to the grid. Veille métier is a regular function (key "veille"), in the reserve by default; it rises on the grid like any function when it needs action. No fixed Veille card on home.
- Bank logos are user-uploaded per bank (private to the company, re-encoded server-side as 128px PNG). Never ship third-party bank logos in the code or the public demo.
- Action (priority) cards: the speaker button sits in the top-right corner next to the close cross; the green action button spans the full card width, centered.
- Home greeting is centered; under it the date and the status are two chips: green "À jour" when nothing is pending, orange "N action(s) à traiter" otherwise.
- Treasury bank view: tapping a bank re-renders the same dial at the exact same height (back arrow, bank name, status, balance, flows, then the same three buttons; a bank in deficit shows its funding alert by default in the row area). Animations (ring fill, amount count-up, staggered rows, pulsing alert dot) must stop under prefers-reduced-motion, leaving a short fade only. The public demo renders this same dial from synthetic data (demo-treasury.js), never a separate layout.
- Function dial ("cadran des fonctions", static/module-focus.js): tapping a function on the home grid opens it in place, in a frame of exactly the grid's size and position (no screen change, no scroll, never grows; on small grids secondary parts are dropped instead). Grid and "Réserve de fonctions" are hidden; the frame (covering the whole block: grid + Réserve button, so nothing below moves) shows header (apps button ⋯ "Toutes les fonctions" on this first level, icon, name, status), 3 key figures, up to 3 read-only lines from GET /api/companies/{cid}/module-peek/{key}, "Voir tout →" (opens the full function panel) and "＋ Nouveau …" when relevant, then a small strip of the other grid functions to switch inside the frame. The apps button or Escape restores the grid. Second-level windows opened from the frame (Voir tout, Nouveau, forms) dock exactly on the visible frame (user request 2026-10-19): dark app colors, a header with the apps button (straight back to all functions) and ONE back button showing the number of steps back to the frame ("‹ 3"), no bottom close bar, and a ⤢ button to deploy full screen when needed. The app strip stays visible and usable under a docked window (switching closes the window and opens the other function in the frame). The strip never moves vertically (horizontal swipe only) and shows each function's name on a translucent band that scrolls with the icons. Panels opened elsewhere keep their usual close cross and bottom close button.
- Direct windows (since 19/10/2026): tapping a function (grid or strip) or an action card opens its full window directly, docked on the function frame and covering the "Vos modules" row just above (moduleFocusWindow); the summary dial is never shown (`.is-direct`). The Assistant IA moves into the window header in place of the title (#dockAssistant) and opens on top (back returns). Closing the window returns to the home grid. Keyword « RETOUR AVANT FENÊTRE DIRECTE » in docs/SAUVEGARDES.md.
- Live site check (.github/workflows/live-check.yml, tests/live_check.cjs): after each push to main (waits 5 min for Railway) and every 4 hours, GitHub opens the LIVE site read-only (health, /demo, and with LIVE_EMAIL/LIVE_PASSWORD secrets a dedicated test account) and publishes captures to captures/live-<date>.
- Visual review: tests/screens.cjs captures every screen at iPhone size after the UI tests; on push runs, CI publishes them to a branch captures/<sha7>-<attempt> that Claude fetches and looks at before asking to merge.
- Option C (inline-actions.js): an action that can be finished in place (equipment repair/revision, risk control, task, client check) unfolds under its home card, list row (list-status) or actions-window row: details + finishing buttons (one API call) + "Voir le détail". Other action types still open their window.
- The app strip (#dockAppBar, maximized windows) lives inside the top window (last row of #contextPanel, or pinned at the bottom of an open form sheet), never fixed over it. tests/module_focus.cjs checks in every function window that primary buttons are reachable (not covered) and that no two controls are stuck together (< 6px).
- List rows in windows (static/list-status.js): rows matching a pending priority action (data-asset/risk/task-open/client-open/quote-open/mail-open/activity-open/social-post) get .row-todo + a .row-chip with the action label; rows with nothing to do get .row-quiet (grey); ISO dates in rows become clear words. Tables stack into blocks on phones and never keep a white hover row.
- Typing mode for every window and form (moduleDockKeyboard → body.kb-open): the window fills the visual viewport above the keyboard, the context footer, sheet handle, header speaker and app bar hide, the active field scrolls to the middle.
- Action cards (formula C, chosen 19/10/2026): one-line titles ending with … (no wrap), state chip + friendly date (priorityFriendly: aujourd’hui/demain/le 5 janv.) on one line, 42px green button. Several actions ("Voir les N actions", "Toutes les actions") open as the `actions` window route (renderPriorityGroupPanel), never a modal.
- Treasury dial folds (banks.js bankDialOpen, localStorage aia-treasury-open, folded by default): folded = health ring + balance + month in/out + any alert (always, with its funding button); a tap on the chevron, title, ring or balance unfolds the full dial (tabs, bank pills). Tests that need the full dial set the key in an init script.
- Windows open maximized by default (moduleDock.preferExpanded, moduleDockSetExpanded): home blurred behind, app strip as #dockAppBar at the bottom; ⤡ puts the window back on the function frame and that choice is kept for the next windows until reload.
- Swipe back (static/edge-back.js): a swipe from the left edge to the right = one step back (same as ‹ / #dockBack; at the first step it closes the window). Only in the home-screen app (standalone) — Safari tabs already do it natively. Vertical moves are scrolls. HTML pages are served with Cache-Control no-cache so a new version shows on the next opening.
- Windows never nest boxes: static/dark-surfaces.js tags every framed/padded block spanning ≥45% of a window with `.box-flat` (flattened to a plain section with a separator), so a card inside a card never narrows the content; every window keeps the full width of the first. In full screen (⤢, `dock-expanded`) the app strip stays available as a fixed bar `#dockAppBar` under the window; touching an app closes the window and switches the dial. tests/module_focus.cjs opens every function window from the dial and checks both.
- Glass design (static/wallpaper.js): each user picks a home wallpaper from the account menu (« Fond d’écran »), saved in `users.wallpaper` via PUT /api/me/wallpaper (presets only, default `nuit`). Home cards and windows are frosted glass (`body[data-wall]` rules at the end of home-reference.css), darker on bright wallpapers. Backups and the « RETOUR AVANT VERRE » keyword: docs/SAUVEGARDES.md.
- Every second-level window (floating panels, dialogs, forms) uses the app's dark universe like the function dial (user request 2026-10-19): dark surfaces, light text, dark fields with light text, green primary buttons. static/dark-surfaces.js tags leftover light backgrounds / dark ink from older page styles so nothing is ever white-on-white; fields never overflow the window; a docked window shows a single back arrow.
- Typing in a docked window: while the keyboard is open, the window fills the whole visible area between the top safe area (camera) and the keyboard, keeping the active field in view; when the keyboard closes it returns exactly onto the function frame (user request 2026-10-19).
- Guided entry in every window form (static/form-guide.js, user request 2026-10-19): keyboard key "Suivant" moves to the next empty field and "OK" on the last one brings the validate button into view (never submits by itself); dates/lists/10-digit phones/5-digit postal codes move on by themselves; current field outlined and kept in view; "n / N" progress for 3+ fields; the validate button stays visible at the bottom (grey until required fields are filled). Chat and fields marked data-no-guide are left alone.
- Exports (`/api/...-export`) never navigate away: static/in-app-files.js fetches the file and hands it to the share sheet (save to Files, mail…), or downloads it on computers. Light badges/buttons inside windows are tinted for the dark theme; the active field shows one single green ring (no double outline), and the sticky validate button returns to the flow while typing so it never covers the next field.
- Action cards on home: the green button IS the function's button (user request 2026-10-19, "aucune différence"): it opens the matching function in the function dial (brought into view) and nothing else. The dial lists that function's pending actions first (tappable rows); a tap opens the action's window docked on the frame. Routine/example cards keep their direct action.
- Action mode strip (user request 2026-10-20): a window opened from an action card (moduleFocusFromPriority → moduleDock.actions) shows in its app strip only the functions that still have actions (action_counts > 0, plus the current one), each with an orange count; touching one opens its actions directly (one action: its window; several: the `actions` list). A function opened from the grid keeps the full strip.
- Phone habits, not a copy of the phone (static/native-fields.js, user request 2026-10-20): every field gets the phone's own keyboard and autofill through attributes only (inputmode tel/email/url/decimal/numeric, autocomplete, autocapitalize, enterkeyhint=search), never by changing its type or redrawing a picker. Dates and lists stay native inputs/selects (wheel on iPhone, calendar on Android); back works with the system gesture/button through history. Keep the green validate button at the bottom (thumb reach). tests/module_focus.cjs checks the keyboards in every window.
- Phone habits 2 (2026-10-20): static/contact-links.js puts a small button under every filled phone / e-mail / address field of a window (Appeler → tel:, Écrire → mailto:, Itinéraire → Plans on iPhone, Google Maps elsewhere), hidden while empty. static/pull-refresh.js: pulling the home down refreshes it (refreshCockpit), only in the home-screen app; windows keep pull-down-to-close. static/row-swipe.js: swiping an action row (list-status rows, actions window) to the left reveals its first finishing button (inlineActions.run); tap elsewhere closes. tests/phone_habits.cjs.
